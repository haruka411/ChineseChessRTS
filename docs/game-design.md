# 中国象棋 RTS 开发文档

## 1. 项目目标

本项目是一款以中国象棋棋盘和棋子走法为基础，加入即时操作、资源采集、单位建造、移动冷却、AI 对战和可回放日志的策略游戏。

当前目标是完成可玩的单机网页原型，后续再考虑 Windows 桌面封装。

目标平台：

- Web：现代桌面浏览器，当前使用 Vite 开发服务器。
- Windows：后续可用 Electron 或 Tauri 封装同一套 Web UI。

当前技术栈：

- React + TypeScript。
- 棋盘、棋线、棋子、矿点、候选点使用 SVG / DOM 混合渲染。
- 游戏规则集中在 `src/game/rules.ts`。
- AI 逻辑集中在 `src/game/ai.ts`。
- 简体中文、繁体中文、英文三语言文本集中在 `src/i18n.ts`。

当前不使用 Phaser 或 PixiJS。PixiJS 曾做过试验，但稳定版本已回到 React + SVG / DOM。理由是本阶段棋盘元素数量少，SVG 足够清晰，调试和布局更直接；后续若需要大量动画、粒子或复杂缩放，再重新评估 PixiJS。Phaser 暂不适合当前阶段，因为它的场景、输入和 UI 生命周期会与 React 应用结构产生较多重叠。

## 2. 当前玩法

双方在同一张中国象棋棋盘上实时操作，不分回合、不分先后。玩家可在开局前选择红方或黑方，AI 自动控制另一方。双方通过占据矿点获得金钱，并消耗金钱建造棋子。棋子按照中国象棋基础走法移动和吃子，但胜负条件改为必须实际吃掉对方将/帅。

核心循环：

1. 选择己方棋子。
2. 查看合法候选点。
3. 移动或吃子。
4. 棋子进入移动冷却。
5. 可采矿棋子占据矿点，周期性获得金钱。
6. 消耗金钱建造新棋子。
7. 通过占矿、建造、调度和进攻吃掉对方将/帅。

## 3. 棋盘与坐标

棋盘为标准中国象棋棋盘：

- 9 路，10 横线。
- 中间有楚河汉界。
- 双方各有九宫。
- 棋盘坐标与棋盘格线对齐。
- 不显示 LilyProject 左侧横线坐标。

内部坐标：

- `x`: 0 到 8，从红方左侧到红方右侧。
- `y`: 0 到 9，从红方底线到黑方底线。
- 红方底线为 `y = 0`。
- 黑方底线为 `y = 9`。

显示坐标：

- 红方底部使用中文数字：九、八、七、六、五、四、三、二、一。
- 黑方顶部使用阿拉伯数字：1、2、3、4、5、6、7、8、9。
- 玩家选择黑方时，棋盘切换为黑方主视角：黑方在下方，红方在上方，上下坐标和点击换算同步翻转。
- 传统记谱根据行动方视角生成进、退、平。

当前点击方式：

- 棋盘只保留整板点击层。
- 点击时根据棋盘矩形尺寸换算到最近交叉点。
- 棋盘内棋子文字、矿点图标、SVG 文本等元素不可被选中，避免拖拽时出现文本选择。
- 不再保留 90 个 `button-cell` 作为命中区域。

## 5. 矿点与资源

矿点总数为 10 个：

| 类型 | 红方侧 | 黑方侧 |
| --- | --- | --- |
| 九宫中心 | `(4, 1)` | `(4, 8)` |
| 将帅初始位置 | `(4, 0)` | `(4, 9)` |
| 中兵/中卒位置 | `(4, 3)` | `(4, 6)` |
| 河沿象相可达点 A | `(2, 4)` | `(2, 5)` |
| 河沿象相可达点 B | `(6, 4)` | `(6, 5)` |

可采矿棋子：

- 仕 / 士
- 相 / 象
- 帅 / 将
- 兵 / 卒

不可采矿棋子：

- 车
- 马
- 炮

采矿规则：

- 当可采矿棋子站在矿点上时，该阵营每 10 秒获得 5 金钱。
- 每个矿点独立计时。
- 收入事件会写入结构化日志，但当前记谱面板不显示收入事件，避免记谱过密。
- 矿点图标在空矿点显示在棋盘交叉点上；棋子站上去时，矿点图标上移到棋子上方，避免被盖住。
- 采矿进度使用环形计时条，颜色参考 LilyProject 的绿色表现。

## 6. 棋子走法

棋子沿用中国象棋基础移动规则：

- 车：横竖直线移动，中间不能有子。
- 马：走日，受蹩马腿限制。
- 炮：移动同车；吃子时必须隔一个炮架。
- 相/象：走田，受塞象眼限制，不可过河。
- 仕/士：走斜线，只能在九宫内。
- 帅/将：通常只能在九宫内横竖移动一格；若双方将/帅位于同一路且中间无子阻隔，可沿该路直接吃掉对方将/帅，即白脸杀/飞将。
- 兵/卒：过河前只能向前；过河后可向前或左右，不能后退。

本游戏允许将帅照面。

实现状态：

- 已实现白脸杀/飞将：将/帅可在同一路无遮挡时直接吃对方将/帅。
- 已允许将帅照面：其他棋子可以移开，使双方将/帅同路无遮挡。

本游戏不使用传统“将军必须应将”的流程。即使出现威胁，只有实际吃掉将/帅才会结束游戏。

## 7. 实时操作与冷却

双方实时行动：

- 不分回合。
- 玩家可随时选择自己阵营的棋子。
- AI 按自己的调度逻辑操作玩家未选择的一方。

移动冷却：

- 棋子完成移动或吃子后，进入独立移动冷却。
- 冷却中可以选中棋子。
- 冷却中不能移动或吃子。
- 棋子基本走法沿用中国象棋，但本作允许将帅照面。
- 移动 CD 只显示环形计时条，不显示数字。

当前移动冷却：

| 棋子 | 冷却 |
| --- | --- |
| 帅 / 将 | 4 秒 |
| 仕 / 士 | 4 秒 |
| 相 / 象 | 6 秒 |
| 车 | 10 秒 |
| 马 | 8 秒 |
| 炮 | 8 秒 |
| 兵 / 卒 | 6 秒 |

游戏结束后，游戏计时器停止推进。

建造限制：

- 目标格必须为空。
- 金钱必须足够。

- 当前玩家只能建造自己选择阵营的棋子；AI 可按逻辑建造另一阵营的棋子。

建造位置：

- 车、马、炮、兵/卒只能建造在该棋子可能的初始位置。

## 9. 胜负规则

胜利条件：

- 一方实际吃掉对方将/帅后立即获胜。

当前不存在：

- 将死胜利。
- 困毙胜利。
- 长将判负。
- 和棋判定。

## 10. 记谱、日志与回放目标

当前记谱面板显示：

- 移动。
- 吃子。
- 建造。
- 胜负结果。
- 失败操作。

当前记谱面板不显示：

- 采矿收入事件。
- 对局开始事件。

显示策略：

- 不再写“红方/黑方”前缀。
- 通过事件文字颜色区分阵营。
- 红方记录使用红色。
- 黑方和 AI 记录使用蓝色。
- 每条记录带开局后时间戳，例如 `[00:12.350]`。

传统记谱规则：

- 普通情况使用“棋子 + 原路 + 进/退/平 + 目标”格式，例如 `兵五进一`、`车九平八`。
- 若同一纵线上有同阵营、同兵种的多个棋子，使用前缀区分，但仍保留原纵线：
  - 两个同类棋子：`前兵五进一`、`后车九退二`。
  - 三个同类棋子：`前兵五`、`中兵五`、`后兵五`。
  - 超过三个同类棋子：从前到后使用 `前`、`二`、`三`、...、`后`，例如 `二兵三平二`。这是对本游戏可建造多个同类棋子的扩展规则。
- “前/后”按行动方视角计算：红方向黑方为前，黑方向红方为前。
- 马、相/象、仕/士按标准中国象棋记谱使用 `进/退 + 目标路数`，例如 `马二进三`，不写成 `马二平三`。
- 吃子仍在事件文本中额外显示目标，例如 `[00:12.350] 前兵五进一 吃 卒`。

结构化日志目标：

- 日志必须足以从初始局面还原整局。
- 移动事件需要保留传统中国象棋记谱文本。
- 建造事件需要保留棋子类型、位置、花费和时间。
- 收入事件虽然不显示在记谱面板，但应保留在结构化事件中。
- 后续回放应按 `gameTimeMs` 顺序重放事件。

当前 `GameEvent` 基础字段：

```ts
type GameEvent = {
  id: string;
  gameTimeMs: number;
  actor: "red" | "black" | "system" | "ai";
  type: "game_start" | "move" | "build" | "income" | "game_end" | "command_failed";
  messageKey: string;
  messageArgs?: Record<string, string | number>;
};
```

后续为了严谨回放，建议把 `messageArgs` 扩展为稳定 payload，至少包含：

- `pieceId`
- `from`
- `to`
- `capturedPieceId`
- `moneyBefore`
- `moneyAfter`
- `cooldownUntilMs`
- `ruleVersion`

## 11. AI 对战

当前只支持人类玩家对 AI：

- 玩家可选择红方或黑方。
- AI 控制玩家未选择的一方。
- 暂不做人与人联网对战。

AI 当前定位是原型启发式 AI。后续目标：

- 优先保护己方将/帅。
- 优先寻找吃掉对方将/帅的机会。
- 优先占据矿点。
- 根据金钱和局面建造棋子。
- 避免无意义重复操作。
- 根据冷却时间调度可行动棋子。

## 13. 国际化

必须支持：

- 简体中文。
- 繁体中文。
- 英文。
- 首次启动根据浏览器语言自动选择：`zh-Hans` / `zh-CN` 等进入简体中文，`zh-Hant` / `zh-TW` / `zh-HK` / `zh-MO` 等进入繁体中文，其他语言进入英文。
- 用户手动切换语言。
- 用户选择持久化到 `localStorage`。

注意：

- UI 文案走翻译 key。
- 棋子字形始终使用中文；繁体界面使用繁体棋子字形。
- 传统中国象棋记谱保留中文格式。
- 结构化日志不能依赖本地化文本还原局面。

## 14. AI

当前 AI 使用自研搜索与策略配置，不依赖外部象棋引擎。每局 AI 会隐藏选择一种模式：

- 激进：只守约 4 个本方矿，尽快转入进攻。
- 平衡：守 5 个本方矿后转入进攻。
- 经济：守住本方矿后继续争夺对方矿点。

搜索评估同时考虑将帅安全、可吃王机会、材料、矿点、建造点堵塞、对方底线车马建造点控制、闲置金钱和冷却期内的潜在被吃风险。游戏胜利条件仍是实际吃掉对方将帅，所以直接吃王与制造强王威胁高于纯经济收益。

保留未来方向：

- 记录自博弈数据，继续调权或训练轻量策略模型。
- 可把外部战术评估器作为参考特征，但不让它接管资源、建造、冷却和实时调度。
